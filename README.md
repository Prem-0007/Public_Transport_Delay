# Public Transport Delay Analysis & Prediction

A data analytics and machine learning project for exploring, analyzing, and predicting public transport delays using a Flask web application and scikit-learn models.

The application combines data cleaning, exploratory data analysis (EDA), interactive visualizations, machine learning, and batch prediction in one dashboard.

## Project Overview

Public transport delays can affect passenger experience, route planning, and operational efficiency. This project demonstrates how data analytics and machine learning can be used to understand delay patterns and estimate potential delays.

The application supports two prediction tasks:

- **Regression:** Predicts delay duration in minutes.
- **Classification:** Predicts whether a journey is delayed by more than five minutes.

The project uses a simulated transport dataset generated with a fixed random seed. It is intended for educational and demonstration purposes.

## Features

- Automated data cleaning and preprocessing.
- Missing-value handling, duplicate removal, and outlier treatment.
- Interactive dashboards with filters and hover tooltips.
- Exploratory analysis using 15 visualizations.
- Multiple regression and classification models.

- Model evaluation, residual analysis, and feature importance.
- Individual and batch predictions.
- CSV upload and downloadable prediction results.
- Flask-based web interface and JSON prediction API.
- Saved machine learning pipelines for reuse.

## Dataset

The dataset is generated by `generate_dataset.py` using random seed `42`.

| Property | Details |
|---|---|
| Date range | January 1 – December 31, 2025 |
| Routes | 12 |
| Transport modes | Bus, Tram, Metro, Train |
| Raw dataset | 6,060 rows × 17 columns |
| Cleaned dataset | 6,002 rows × 20 columns |
| Duplicate rows removed | 58 |
| Missing cells in raw data | 729 |
| Missing cells after cleaning | 0 |
| Regression target | `delay_minutes` |
| Classification target | `is_delayed` |

The classification target is defined as a delay greater than five minutes.

### Data Cleaning

The preprocessing pipeline includes:

1. Removing duplicate records.
2. Imputing missing values.
3. Standardizing 40 inconsistent weather labels.
4. Capping 26 extreme delay outliers at approximately 30.2 minutes.
5. Creating three additional features.
6. Preparing consistent inputs for training and prediction.

The raw and cleaned datasets are stored in the `data/` directory. The application provides a Dataset page with additional statistics and a data dictionary.

## Installation and Setup

### Prerequisites

- Python 3.10 or another Python version supported by the project's dependencies.
- pip package manager.
- Git, if cloning the repository.

### 1. Clone the repository

```bash
git clone https://github.com/Prem-0007/Public_Transport_Delay.git
cd Public_Transport_Delay
```

### 2. Create a virtual environment (recommended)

**Windows:**

```bash
python -m venv .venv
.venv\Scripts\activate
```

**Linux / macOS:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

```bash
python -m pip install -r requirements.txt
```

### 4. Start the application

```bash
python app.py
```

Open the following URL in your browser:

http://127.0.0.1:5000

On Windows, you can alternatively double-click `run.bat`. On Linux or macOS, use:

```bash
bash run.sh
```

### Optional: Regenerate the dataset and train models

To regenerate the simulated dataset:

```bash
python generate_dataset.py
```

To rerun preprocessing, exploratory analysis, model tuning, and training:

```bash
python train.py
```

Training may take approximately three minutes, depending on your hardware and configuration.

**Note:** Regenerating data or retraining models may replace existing generated files or model artifacts. Back up any customized data before doing so.

## Machine Learning Workflow

The project follows this workflow:

1. Generate or load the transport dataset.
2. Clean the data and handle missing values.
3. Perform exploratory data analysis.
4. Prepare features and target variables.
5. Train regression and classification models.
6. Tune selected model hyperparameters.
7. Evaluate model performance.
8. Save fitted pipelines and model results.
9. Load the saved artifacts in the Flask application.
10. Generate individual or batch predictions.

The shared `src/preprocessing.py` module helps keep preprocessing consistent between training and application inference.

### Regression Models

- Linear Regression
- Random Forest Regressor
- Gradient Boosting Regressor

### Classification Models

- Logistic Regression
- Random Forest Classifier
- Gradient Boosting Classifier

Random Forest and Gradient Boosting configurations use hyperparameter search as described in the training workflow.

## Prediction API

The Flask application provides a prediction endpoint:

`POST /api/predict`

The endpoint accepts JSON input and returns a prediction as JSON.

Example request structure:

```json
{
  "route_id": "R1",
  "hour": 8,
  "weather": "Clear"
}
```

Example using `curl`:

```bash
curl -X POST http://127.0.0.1:5000/api/predict \
  -H "Content-Type: application/json" \
  -d '{"route_id":"R1","hour":8,"weather":"Clear"}'
```

**Important:** This is an illustrative request based on the documented input fields. Confirm the accepted values and any additional required fields in the application's implementation before using it. The actual response structure depends on the API implementation.

## Model Evaluation

The project evaluates regression models using:

- Mean Absolute Error (MAE)
- Root Mean Squared Error (RMSE)
- Coefficient of Determination (R²)
- Five-fold cross-validation

Classification models are evaluated using:

- Accuracy
- Precision
- Recall
- F1-score
- ROC-AUC
- Confusion matrices

Additional diagnostics include residual analysis and permutation feature importance.

Refer to the saved model results and the Models page for actual experimental metrics. No model is guaranteed to perform best on new or real-world data.

## Limitations

- The current dataset is simulated rather than collected from a live transport system.
- Predictions may not generalize to actual routes, operators, or cities.
- Performance depends on data quality, feature selection, and training configuration.
- Delay estimates should not be treated as guaranteed arrival times.
- The application requires compatible dependencies and available trained model artifacts.
